# Учебный Multics (`multics_sim`)

Учебная программная модель ключевых архитектурных механизмов операционной системы **Multics**.
Модель воспроизводит механизмы на уровне *понятий* (не эмулирует аппаратуру GE-645 / Honeywell 6180)
и **выводит в консоль подробный протокол действий ядра**, чтобы студент видел, что происходит внутри.

Что смоделировано:

| Механизм Multics | Где в коде | Что можно наблюдать |
|---|---|---|
| Сегменты и таблица известных сегментов (KST) | `segment.py`, `process.py` | «всё есть сегмент», номера сегментов |
| Иерархическая файловая система (`>`, `<`, ссылки, add_name, звёздные имена, квоты, safety switch) | `filesystem.py`, `starname.py` | команды `list`, `tree`, `link`, `add_name` |
| ACL (Person.Project.tag, наиболее конкретная запись) | `acl.py` | `set_acl`, `list_acl` |
| Кольца защиты 0–7, кольцевые скобки, шлюзы | `rings.py`, `access.py` | `effective_access`, вход в шлюз 4 → 0 |
| Виртуальная память: страницы, кадры, page fault; clock / FIFO / LRU | `memory.py` | `memstat`, `page_table`, `set_policy` |
| Динамическое связывание: linkage fault, правила поиска, защёлкивание | `linker.py` | `run`, `print_linkage`, `list_ref_names` |
| Процессы и планировщик round-robin | `process.py`, `scheduler.py` | `start`, `ps`, `schedule` |
| Командный процессор, ~100 команд, 61 активная функция, `exec_com` | `shell.py`, `commands/` | `help`, `help -af` |

Все сообщения ядра выводятся с префиксом `[ядро]` или `[ядро, кольцо 0]`.

## Требования

* Python **3.12+**
* Только стандартная библиотека, устанавливать ничего не нужно.
* Работает в Windows, Linux и macOS (в Windows консоль автоматически переключается в UTF-8).

## Быстрый старт

```bash
git clone https://github.com/faxvex/multics_simulate.git
cd multics_simulate

python -m multics_sim --demo   # демонстрационный сценарий (все механизмы подряд)
python -m multics_sim          # интерактивная оболочка
```

В Windows можно запустить `run.bat`.

Учётные записи по умолчанию (логин → пароль):

| Пользователь | Пароль |
|---|---|
| `Ivanov.Students` | `ivan` |
| `Petrov.Students` | `petr` |
| `Guest.Visitors` | `guest` |

Вход: `login Ivanov.Students ivan`. Справка: `help`, `help -af`.
Пример готового вывода демо: [`docs/demo_output.txt`](docs/demo_output.txt).

## Использование на занятиях

Три уровня работы: **демонстрация** (преподаватель показывает `--demo` и разбирает лог),
**управляемый эксперимент** (студент выполняет готовый сценарий) и **свободный эксперимент**
(студент меняет ACL, кольцевые скобки, политику замещения страниц, запускает параллельные задачи).

Готовые сценарии с командами и вопросами для обсуждения: [`docs/scenarios.md`](docs/scenarios.md).
Контрольные вопросы с эталонными ответами для тестирования студентов: [`docs/assessment_questions.md`](docs/assessment_questions.md).

## Тесты

```bash
python -m unittest discover -s tests -v
```

74 теста покрывают разбор путей, ACL, кольцевые скобки и шлюзы, page fault и три алгоритма
замещения, linkage fault, планировщик и основные группы команд.

## Структура репозитория

```
multics_sim/
  system.py        ядро (System)
  shell.py         командный процессор
  access.py        проверка доступа: ACL + кольцо
  memory.py        виртуальная память
  linker.py        динамический компоновщик
  scheduler.py     планировщик round-robin
  commands/        команды и активные функции
  demo.py          демонстрационный сценарий
tests/test_multics.py
docs/              сценарии занятий, пример вывода
```

## Упрощения модели

* нет эмуляции машинных команд и 36-разрядных слов — используется мини-язык исполняемых сегментов;
* малые страницы (64 символа) и малое число кадров (4) — чтобы page fault были видны;
* номер сегмента назначается объекту ФС один раз (в оригинале — в каждом процессе);
* права на промежуточные каталоги пути при разрешении имени не проверяются;
* время виртуальное: один такт — одна инструкция мини-языка;
* состояние системы между запусками не сохраняется.
